## 一、已确认的 major 问题

### M1. 所有 fresh_* 几何共用同一个随机种子，载荷函数跨几何重复（DATA-1）
- **问题**：`seed = (int.from_bytes(case.encode(),'little') + 7919) % 2**31` 按小端取字节再模 2^31，结果只取决于名字的前 4 个字符 `fres`。所有 `fresh_*` 的种子都是 1936036181。旧的 prep_geo.py 也有同样的碰撞，种子是 1936028262。
- **证据**：`prep_geo2.py:409`，`prep_geo.py:225`。本地复现：4 个不同名字得到同一个种子。`prep_data.plane_waves` 每次抽取的随机数个数与坐标 X 无关，所以同一个面集的几何上，第 j 个样本的波矢、相位、幅值、patch 宽度、弹簧 alpha、only_n 掩码和 randperm 全部相同。唯一的例外是 patch 中心，它由 `randint(0, X.shape[0])` 决定，会随求积点数变化。
- **影响**：约 150 个几何的每一类，实际上只由约 512 个"共享载荷函数"构成，并不是彼此独立的抽样。同一家族的 FULL/r1/r2 在共享面上的载荷几乎一样。所有 val 几何都在同一组 64 个函数上评估，因此各类均值之间强相关。
  - 没有 train/val 泄漏。
  - 这个效应对所有臂相同，所以不会让臂之间的比较产生系统偏向；但有效样本多样性远低于设计值。
- **建议修复**：种子改为 `int(hashlib.sha256(case.encode()).hexdigest()[:8],16)` 加上类别偏移，并且每个类用独立的 generator（同时解决 DATA-8c）。旧种子放在 flag 后面保留，旧数据树不动。
- **全量训练前必须修？** **是，而且要在全量数据准备之前修。**

### M2. force_c / face_c 用欧氏刚体投影做平衡，给所有端口加上了"非一致的均匀节点载荷"（DATA-2）
- **问题**：随机牵引力的合力和合力矩不为零。当前的做法是：
  - force_c 在 `C.neumann` 里用 `f - Q Qᵀ f` 去掉合力和合力矩。Q 是覆盖**全部端口节点**的正交刚体基，包括 box、虚拟 fringe 和 cut 带，所以相当于在每个端口 DOF 上叠加了一个均匀平移载荷和一个线性转动载荷。
  - face_c 用 `Rf` 在 T.nodes 上做同样的事，而 T.nodes 包含 fringe 节点。
  - 结果是文档里"fringe 几乎不受力"和"90% 样本 cut 面不加载"这两句话，描述的是投影**之前**的 f，而不是实际施加的载荷。
- **证据**：`prep_geo2.py:151`（force_c）、`:168`（face_c `F[dofs] = ff - Rf @ (Rf.T @ ff)`）、`teacher.py:284`。用同一套生成器在 6 面网格上做的玩具检验：被移除部分占比 ‖QQᵀf‖/‖f‖ 的中位数约为 0.35（波）和 0.37（patch）。
- **影响**：每个 force_c/face_c 载荷里，有相当一部分其实是"均匀节点载荷"，而这种载荷已被规定只作压力测试、不进门禁。
  - r2 pilot 中"一致牵引力类使柔度改善 15–28%"的结论，是在这个混合类上测出来的，其中有多少来自一致载荷、有多少来自均匀分量，目前分不开。
  - 它与 gate y load-6 灵敏度上升（2.06%→3.0%）是否相关，仍是假设。
  - support_k 和 glued 有约束、不做投影，不受影响。
- **建议修复**：在牵引力空间内做平衡。令 G = QᵀA（6×3m），取 t ← t − Gᵀ(GGᵀ)⁻¹G t，或者在加载求积点上拟合并减去刚体型牵引 a + b×(x−x_c)。这样 f = A t 既一致又自平衡，neumann 里的投影就变成空操作。把 ‖QQᵀf‖/‖f‖ 记进 DONE2 作为检验（修复后应在 1e-6 量级）。
- **全量训练前必须修？** **是，在数据准备之前修。** 另外，r2 pilot 关于新类收益的结论要在修复后的数据上重新确认。

### M3. 选模只看恒等视角，且指标与门禁不一致（TRAINER-1 与 GATE-5 合并）
- **问题**：
  - oh=true 时训练在 48 个视角上随机进行，但 evaluate、mu、cert 以及 best.pt 的选取只用恒等视角。
  - score 用的是均值能量 + 均值灵敏度 + 0.5·p90，按族平均。门禁看的却是 12 个一致载荷下柔度**和**每 cell 8 角灵敏度的**最大值**。
  - train1（r2 pilot 用的训练器）选模只看最差类的均值**能量**，没有灵敏度项；pilot 还把最接近门禁的 force_c/glued 排除在选模之外。
- **证据**：
  - `train3.py:624`（`g = s_.geo  # identity view`）、`:456-457`（只在 train=True 时设视角）、`:349-364`（score）、`:736-738`（best.pt）。
  - `train1.py:101,104`；g_chain3.sh 只对 best.pt 做门禁。
  - 实测：c_oh 的 best 是 5k 步，旋转视角误差 11.8/13.0/6.3%；last（15k）只有 6.8/7.9/4.2%，前者约差 2 倍。
- **影响**：v2 O_h 全量训练的 best.pt 会系统性地偏向"恒等视角好、旋转视角差"的早期检查点，而且没有任何信号提示。门禁看的是灵敏度，选模却主要看能量，所以被门禁和部署的检查点未必是同一轮训练里最好的那个。
  - 降级理由：docstring 写明了这个行为，门禁 cell 本身是原始朝向，用 last.pt 可以规避。
- **建议修复**：
  - 新增 cfg `eval_views`（默认 `[0]`，保持旧行为；v2 用 `[0,5,17,29,38,46]`）。对每个 val/probe 几何、每个视角 k，调用 `OH.view → eval_geo → OH.drop`。
  - score = 各视角族分数的均值，可再加最差视角；恒等分数单独记录。
  - score 中保留灵敏度的均值和 p90，并把 force_c/glued 纳入（单独记录）。
  - mu/cert 只在恒等视角或一个固定旋转视角上算，以控制成本；配合 `eval_weights='sel'`。
  - 把 eval_views 和各视角分数写进 best.pt/last.pt。
- **全量训练前必须修？** **是。**

### M4. EMA 从热启动权重开始且没有偏差校正，早期 best 实际掺着大量 v1 权重（TRAINER-2 与 GATE-4 合并）
- **问题**：EMA 影子在加载 init（v1 snap_60000）之后才创建，更新是普通的 lerp，没有 1/(1−dᵗ) 校正。decay=0.9997 时，v1 权重的残留比例为：5k 步 22%，10k 步 5%，15k 步 1%。选模用 sel='ema'，每 5000 步评估一次，一共只有 3 个候选。
- **证据**：`train3.py:447`（在 `:434-441` 的加载之后）、`:248`（clone 当前权重）、`:252`（无去偏）、`:587`；g_cfg.sh 中 `ema=0.9997, eval_every=5000, steps=15000`。
- **影响**：
  - 选模被系统性地拉向 v1。v1 从没见过旋转、在恒等视角上最强，这正好加剧了 M3，与 c_oh 选中 5k 的现象一致。
  - 对从 v1 出发且在分布内几乎等价于恒等的臂（B1、B2），早期 EMA 检查点天然彼此接近，可能人为造成"中性"的结论。这一点只是可能，需要看各臂 best 所在步数才能判断。
- **建议修复**：二选一：
  - 用去偏 EMA（影子初始化为 0，除以 1−dᵗ）；
  - 设 `ema_start`，热身后再初始化或重置 EMA；或者 dᵗ > 1% 的评估不参与选 best。
  
  同时把评估间隔缩短到 ≤2500 步。已有的臂同时报告 last 和 raw（score_raw 已有记录）。
- **全量训练前必须修？** **是。**

### M5. train3 没有 strict_mix 检查，mix 中缺失的类被静默丢弃并重新归一化（TRAINER-3）
- **问题**：`HostBanks.sample` 只保留几何实际拥有的类，并对权重重新归一化，train3 不做任何比对。
  - (a) 默认 `bank_source='slot'` 只有 5 个旧类，新类写进 mix 也**从不参与训练**，而且不报错。
  - (b) prep_geo2 会按几何跳过 glued（没有 FULL 父体，或胶合面没有材料）和 support_k，这些几何的其他类配额因此被静默放大。
  - (c) ADV_FAIL 之后 'adv' 会消失。
- **证据**：`trainlib.py:459-461`；`train3.py:95`（默认 slot）；prep_geo2 中 glued 的跳过在 L288/L294，support_k 的跳过在 L446；`train1.py:51-57` 有 MIX_MISSING，train3 没有。
- **影响**：一个"新数据"臂如果忘了设 `bank_source='data'`，训练出来就是对照组，结果却照常输出。全量 v2 训练恰好是最容易踩中这个问题的场景。
- **建议修复**：在 load_host/Slot 中计算 `missing = [c for c in mix if mix[c]>0 and c!='adv' and c not in hb.classes]`，按几何记录 MIX_MISSING。如果某个 mix 类在**所有**几何上都缺失，就直接 raise；`strict_mix=true` 时任何缺失都 raise。adv 丢失作为事件记录。
- **全量训练前必须修？** **是。**

### M6. 臂判定规则是"4 族中 ≥3 族胜出"且没有裕量，复制实验又用了同一种子（GATE-2）
- **问题**：只要比值 < 1 就算这一族胜出，没有噪声模型。在无效应、4 个符号独立对称的零假设下，P(≥3/4) = 5/16 ≈ 31%。c_ctrl2 和 p_ctrl2 只改了 out，seed 相同，所以它们只测到了 cuDSS 或原子操作带来的非确定性，测不到种子之间的方差。每个臂都只跑了一个种子。
- **证据**：`compare_arms.py:51`（`< 1`）、`:68`；g_q.sh；V2 文档自己写明"同种子单步 loss 在重跑之间波动 2–8%，而臂间差异只有 1–4%"。ARCH_REVIEW 中"胜出者用 2 个种子确认"的安排没有实现。
- **影响**：一个无效的臂约有三分之一的概率被判为"更好"。计划中大约有 10 个臂，预计会出现假阳性。目前"B1/B2 中性"和"新数据使 y 灵敏度退化"这类 1–4% 的差异，在统计上都还没有成立。
- **建议修复**：
  - 每个臂和对照组至少跑 2 个**不同 seed**。
  - 族胜出必须超过对照组的种子间离散度，或者在族内按几何做配对符号检验并给出 α。
  - 差异落在噪声内时报告"未定"。
- **全量训练前必须修？** 不影响全量训练的启动。但**任何以 v2 全量结果为依据的决策**都需要这套机制，建议现在就把第二个种子的 GPU 预算排进计划。

### M7. B1 的饱和统计看不到 knee 区间，"分布内等价于恒等"的说法没有依据（INVARIANTS-1）
- **问题**：bound_knee=k>0 时，_SoftClip 在 |x| > T = kA 就开始压缩，但计数只统计 |x| > A。c_b1 用的是 A = 2×标定最大值、knee = 0.5，所以 T 到 2T 整段都在被压缩，却不计数。具体数值：|x| = 1.5T 时输出偏低 2.5%，|x| = 2T 时偏低 11.9%，而 sat_max 始终为 0。
- **证据**：
  - `models.py:413`（`_clip`：`x.abs() > A`）、`:430`（`_transfer`：`sp[j] > A`）。
  - g_b1.sh 中 `b[k] = 2.0*mx`。
  - `train3.py:720-721` 每 50 步只记录当前几何的 sat_max。
  - T 取自 v1 snap_60000 在 40 个几何上的最大值，而 c_b1 又在整个训练池上多训了 15k 步。
  - V2 文档第 13 行和第 19 行的相关表述。
- **影响**：臂实测"中性"这一结论本身仍然成立，但文档给出的理由（"截断从未触发"、"零代价的分布外保险"）没有被证明。sat_stats 作为部署时的 OOD 监测也存在盲区：系数被压缩了约 12% 时读数仍为 0。
- **建议修复**：在 _clip/_transfer 中分别统计 |x| > kA 和 |x| > A，并由 sat_stats 同时报告。然后在 c_b1 的 best/last 上对 train/val/gate 全部几何重新跑 calib_b1 capture，报告每组的 max|x|/T。修正文档的表述。
- **全量训练前必须修？** 如果 v2 启用 B1，计数器要在训练前改好（改动小）。capture 验证属于 GPU 任务，可以和数据准备并行做。

## 三、被驳回或被部分驳回的点

- **GATE-10（整条驳回）**："O_h 违反预注册规则被采纳"不成立。ARCH_REVIEW B6 按用户定的范围引入 O_h，并且预注册了旋转误差 ≤ 1.2× 的目标，恒等视角 +30% 的代价也已公开说明。仍然有效的只有一点：缺少格点级的旋转门禁。
- **INVARIANTS-2 部分**："allow_tf32 只在 diag_tf32 出现"不对，`models.py:36-45` 已有 `set_conv_fp32`/`OPL_CONV_FP32`。"FULL 邻居的 eps 会变负"也不对：精确 cell 的 eps 取 0。因此降为 minor。
- **DATA-3 部分**："方向会呈噪声状"不对。Cholesky 是后向稳定的，误差集中在光滑的软模态上。
- **GATE-1 部分**：p_* 臂不是由 compare_arms 判定的（它只处理 c_ 臂），pilot 的例子不构成"规则误判"。
- **GATE-3 部分**：全量重新准备数据的建议并不依赖 p_A/p_B 的 ✅，文档自己已经把 y load-6 列为退化。
- **GATE-7 部分**：现有 evalnet 结果全部来自 0020 家族，不受影响。
- **GATE-8 部分**：TF32 是历史上一直没动的默认值，不是有人"选用的有损加速"。

## 五、其余已确认的 minor 项（一行一条）
