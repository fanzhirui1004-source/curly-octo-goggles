# CutFEM super-element operator learning — state and measurements, 2026-09-15

Self-contained briefing. All numbers below are measured on our machines unless marked as an
estimate or an inference. Where a quantity is a one-sided bound from an iterative estimator rather
than an exact eigendecomposition, it is labelled.

---

## 1. Scientific setting

**Goal.** Learn a geometry-conditioned neural operator that reproduces the interface Schur
complement of a TPMS (P-type sheet) unit cell, so that predicted modules can be assembled into
lattices and used inside topology optimisation.

**Why static condensation rather than homogenisation.** Homogenisation assumes a complete unit cell
and periodic boundary conditions. Both fail for *cut* cells and *boundary* cells, which is exactly
the regime of interest. Static condensation needs no boundary-condition assumption and is exact
against any neighbour.

**Why CutFEM.** All cells live on one common background mesh, so interfaces between neighbouring
modules match by construction and the condensed operators are composable.

**Pipeline.** Geometry (TPMS level set + cut plane) → CutFEM discretisation on a 65³ background
grid, Q2 elements, n = 32 → body stiffness → eliminate interior dofs → Schur complement S on the
cell's complete trace (all dofs on the cell boundary) → remove 6 rigid modes → the label.

---

## 2. The label object

For each identity (unit cell geometry):

- `q` = complete trace dimension (number of trace dofs). Population: 1024 identities, q ranges
  roughly 3 000 – 47 760. Example used throughout: seat 0328, q = 12798, 4266 trace nodes × 3
  components.
- `B` = orthonormal rigid quotient (6 Householder reflectors), maps trace → quotient, `d = q − 6`.
  For 0328, d = 12792.
- `A = B S Bᵀ` = the quotient operator, SPD.
- **The stored label is `R*`**, the upper-triangular Cholesky factor of `A`, stored row-packed in
  float64. `A = R*ᵀ R*`. Full trace reconstruction is `S = Bᵀ R*ᵀ R* B`.

Label sizes: d(d+1)/2 float64. 0328 is 654 MB; the largest identity would be ~9 GB.

## 3. The teacher and its validation status

The teacher is CutFEM **with ghost penalty (GP)** — a stabilisation term penalising jumps of normal
derivatives across faces of cut cells, coefficients γ = η = 1e-4 in our compilation.

A separate line of work (parallel agent, different machine) validated the GP teacher against an
**independent physical reference**: a separately generated body-fitted surface + Tet10 volume mesh,
not using the teacher's G, S or GP energy. Compliance comparison on load spaces:

| what | GP vs finer reference, max compliance difference | reference's own 2-level mesh change |
|---|---:|---:|
| 4 single cells, 6 rigid-fixture load directions | 0.084% – 0.101% | 0.130% – 0.273% |
| 0328, 12 independent finite-area local tractions | 0.253% | 0.502% |
| 2-cell, 2×2×2, 1×1×4 assembled FULL structures | 0.052% – 0.090% | 0.108% – 0.190% |

GP coefficient sensitivity, same load spaces: halving γ changes compliance by 0.007% (6-dim) /
0.020% (12-dim); doubling it by 0.014% / 0.039%.

Assembly consistency (module Schur complements summed on shared dofs vs a direct FE solve of the
union body; each module keeps its own intra-module GP, no cross-module GP added):

| structure | body / trace dofs | displacement rel. diff | compliance max diff |
|---|---|---:|---:|
| two cells | 460 176 / 23 388 | 1.27e-12 | 5.63e-11 |
| 2×2×2 | 1 823 760 / 76 608 | 3.82e-13 | 6.75e-12 |
| 1×1×4 | 918 264 / 44 688 | 1.01e-11 | 6.46e-10 |

Geometry sensitivity along one path: scaling all τ corner thicknesses by (1+ε), central difference
at h = 1e-3 vs 1e-4, whitened by the baseline load compliance → relative Frobenius difference
0.0231%. Nodes and GP faces did change across that perturbation.

**Explicitly not established** (stated by that report): no full-trace stiffness-spectrum comparison
against the independent reference; only FULL (unmirrored) structures assembled, no general oblique
CUT structures; one sensitivity path only, no independent physical gradient; 3 of 16 fixed
identities have unclosed topology rebuilds on that host.

Background: an earlier diagnostic found that a 0.01% thickness perturbation changed the overall
matrix by 0.0234% but changed one complete-boundary direction's stiffness by 59.76%, with 11
directions over a 1.1 stiffness ratio; that perturbation activated a background cell of material
volume fraction ~5.6e-15 and three new GP faces. A controlled rewrite of that stabilisation energy
reduced the neighbouring-geometry max stiffness ratio from ~1.598 to ~1.016.

## 4. The learning problem and its metrics

Student produces an operator `Â`. Whitened spectrum `μ = eig(R*⁻ᵀ Â R*⁻¹)`. Exact log-det
divergence:

```
D = tr(A⁻¹Â) − log det(A⁻¹Â) − d = Σᵢ (μᵢ − log μᵢ − 1) ≥ 0,   zero iff Â = A
```

Reported per mode as `D/d`. Registered gates: **work gate** μ within ±10% on every direction;
**target gate** μ within ±3% and D/d < 1e-4.

In the production code D is computed in closed form (trace identity + log-det with a rank-6 rigid
correction), never by forming the spectrum. A `solve_tol` of 1e-6 on the rigid-correction solve
residual marks a step as numerically unreliable; those steps drop the rigid log-det term.

**Prior state of the neural side.** A single-geometry, free-complete-factor, 100-step run
("N1") ended at D/d = 6.84, μ ∈ [2.27e-4, 379], 9942 of 12792 directions below 0.9, 2671 above
1.1; both gates failed. A separate arithmetic check ("N0": load the true factor, replay) closes at
~1e-12, i.e. the representation reproduces the teacher when handed the exact coefficients.

## 5. Measurement A — free complete factor, one fixed label (seat 0328)

Free upper-triangular `R̂`, no geometry front-end, teacher available. Closed form used:

```
D(R̂) = ‖R̂ R*⁻¹‖²_F − 2 Σᵢ log R̂ᵢᵢ + log det A − d
∇D    = 2 R̂ A⁻¹ − 2 diag(1/R̂ᵢᵢ)      (upper triangle only)
```

D is convex in `Â = R̂ᵀR̂` (trace linear, −logdet convex), unique minimum at `Â = A`.
Evaluator self-check: `D(R*) = 0.000000e+00`, trace term = 12792.000000 = d, exactly.

Stronger, and purely algebraic from the same formula (contributed by an outside review of an
earlier draft of this document, verified here): on the domain of upper-triangular matrices with
positive diagonal, D is **strictly convex in R̂ itself**, since for any nonzero upper-triangular ΔR

```
d²D(R̂)[ΔR, ΔR] = 2‖ΔR R*⁻¹‖²_F + 2 Σᵢ (ΔRᵢᵢ)² / R̂ᵢᵢ²  >  0
```

(the first term because A⁻¹ = R*⁻¹R*⁻ᵀ, the second from −2Σlog R̂ᵢᵢ). Hence R* is the unique
stationary point and the earlier failure cannot be a local minimum of this parameterization. This
statement is confined to the free raw factor: it does not extend to the log-diagonal
parameterization, to the (L, M) parameterization of §7, or to shared network parameters.

Column scale refreshed every 100 steps from the student's own `diag(Â⁻¹)`; Adam's first and second
moments rescaled into the new coordinates at each refresh (a first run omitted that rescaling and
was discarded). 3000 Adam steps, lr 1e-3, same start.

|---|---:|---:|
| teacher `diag(A⁻¹)` | 0.289 | 1.000 |

## 7. Measurement C — capacity of a local operator class (in progress)

The class the existing network head produces:

```
Ŝ = Lᵀ (I + M Mᵀ)⁻¹ L
```

- `L`: upper triangular, nonzeros only on 3×3 node-diagonal blocks and on node pairs within
  radius r = 0.2 in unit-cube coordinates. For 0328 that is ~3.5M free entries.
- `M`: (q × k) dense, k = 1500 here. 19.2M free entries.
- Equivalently `Ŝ⁻¹ = L⁻¹L⁻ᵀ + (L⁻¹M)(L⁻¹M)ᵀ`: a local compliance plus a low-rank addition. Note
  the low-rank term can only make directions *softer*, never stiffer.

**This run removes the network's head bounds** (free entries, diagonal via exp) and applies the
column scaling from A, so it measures the class's capacity rather than the network's feasible set.
Start: `L = diag(1/√c_j)`, M ≈ 0. Adam, lr 1e-3, 22.8M parameters, 0.41 s/step.

| step | D/d | μ_min (upper bound) | μ_max (lower bound) | cond(L) | ‖M‖₂ |
|---:|---:|---:|---:|---:|---:|
| 0 | 1.1194 | 0.0172 | 275.07 | 8.5e1 | 0.15 |
| 1000 | 0.0477 | 0.0732 | 1.195 | 5.06e6 | 10.85 |
| 2000 | 0.0057 | 0.240 | 1.235 | 5.14e6 | 13.72 |
| ~2400 | 0.0036 | — | — | — | — |

μ bounds here are one-sided estimates from block power iteration, not an exact eigendecomposition.
Their direction is nonetheless sufficient to establish failure at step 2000: μ_min ≤ 0.240 exhibits
an over-soft direction and μ_max ≥ 1.235 an over-stiff one, so neither gate is met there. The
converse does not hold — a one-sided bound inside a gate would not establish that the gate is met.
At step 2000: σ_max(L) = 2.07e-1, σ_min(L) = 4.02e-8, bound on cond(K0) = 4.99e15.
17 of the first 1600 steps exceeded the 1e-6 rigid-solve tolerance and dropped the rigid log-det
term. Run continues to 3000 steps.

**R1 end state and why it is superseded.** The run above reached a 200-step mean D/d of about
0.0039 near step 2960 before being stopped. Over its whole trajectory **18 steps exceeded the
rigid-solve tolerance**, and in that code path `divergence_terms` returns the objective with its
rigid log-det term removed while the optimizer still takes the step. Those updates therefore
optimized a different function, so this trajectory can show that the class reaches this magnitude
but cannot be used to attribute the remaining error between capacity and optimization.

### C.1 Four stalled runs, and what the guard was doing

R2 added a rejection rule: a step whose rigid-correction residual exceeds `--solve-tol` is undone,
the learning-rate multiplier is halved, and the rejection counted, so that in principle every
update comes from the complete objective.

| run | `--solve-tol` | rigid refinement | rejection | outcome |
|---|---:|---:|---|---|
| R2 | 1e-6 | none | on | stalled step 281, 45 rejections, residual floor 1.03–1.08e-6 |
| R4 | 1e-6 | 4 | on | 8 rejections by step 208, residual floor ≈1.1e-6 |
| R5 | 1e-4 | 4 | on | stalled step 197, 427 rejections by step 710, residual 1.03–1.19e-4 |
| R7 | 1e30 (never fires) | none | off | ran to step 1199; residual 1.3e-15 → 7.2e+29 by step 300 |
| R8 | 1e30 | none | off, `--gauge-weight 1` | ran to step 1000+; residual 8.6e-12 at step 1000 |

In R2, R4 and R5 the residual floored just above whatever tolerance was configured, which is
consistent with the tolerance being the binding constraint. R7 is not consistent with that
reading: with the rule off the residual does not settle at a floor, it increases monotonically by
44 orders of magnitude over 150 steps while D/d descends smoothly.

One observation about the rule that does not depend on the rest: halving the learning rate does
not change a solve residual, so after the first trigger the rule has no mechanism that could
clear the condition it gates on. R5 rejected 512 consecutive steps.

### C.4 The gauge and its pin

`Â = B K₀ Bᵀ` depends only on `K₀`'s compression to the complement of the rigid modes. For an
orthonormal rigid basis `U` and any `α > 0`, `K₀(α) = BᵀAB + αUUᵀ` gives `B K₀(α) Bᵀ = A`, so
`K₀`'s rigid block and its rigid-to-quotient coupling do not enter the supervised object. The six
rigid zero modes of the predicted Schur complement come from the recovery `Ŝ = BᵀÂB`.

R8 pins the q×6 block `K₀N` to the value the initial operator had, one six-column application per
step. The sweep over the weight:

| weight | rigid residual | identity ÷ direct | direct D/d at step 1000 |
|---:|---:|---:|---:|
| 0 | 2.93e+87 at step 1000 | 2.470 | 0.034952 |
| 0.001 | 9.54e+25 by step 290 | — | — |
| 0.01 | 6.11e+19 by step 290 | — | — |
| 0.1 | 2.68e-13 at step 113, still running | — | — |
| 1 | 8.58e-12 at step 1000 | 1.000 | 0.096171 |

Weights of 0.01 and below reach residuals past 1e19 within 290 steps, which is the unpinned
trajectory with a delay.

**A claim made earlier and now withdrawn:** that pinning a gauge cannot bias the fit. That would
follow if the model could set `K₀`'s rigid block independently of `Â`. It is not obvious that a
banded `L` can, and the measurement is at least consistent with it not being able to: the pinned
run at step 1000 is a factor of 2.75 behind the unpinned one on the direct route, with a much
wider spectrum. What this does **not** separate is how much of that deficit is the penalty
consuming gradient (the gauge loss sits around 1.8e-2 against a total loss near 0.10) and how much
is a genuine restriction on the reachable `Â`.

### C.5 What is open here

- Whether the distorted gradient in the unpinned regime is harmful to the endpoint, or only to the
  reported number. R7 reached a better direct-route D/d than R8 did, which is suggestive but is a
  single pair of runs at one step count.
- Whether a route that is both exact and unconstrained is affordable. Evaluating
  `logdet(B K₀ Bᵀ)` from a Cholesky of `Â` touches no inverse of `K₀` and imposes no constraint.
  Going through `W = L Bᵀ` it is roughly `2d²q + d³/3` ≈ 4.9e12 flops, which on this card is about
  3 s forward and an estimated 9 s per step with backward, against 2.1 s now. That estimate has
  not been validated by running it.
- Whether the collapse has a driver or is a random walk along a direction the objective is flat
  along. It is monotone and accelerating rather than diffusive, which argues for a driver, but no
  mechanism has been isolated. One candidate that has not been tested: `logdet K₀` is read exactly
  off the diagonals of `L` and `C` while the other term comes from a degrading solve, so an
  imperfect cancellation could leave a small systematic descent.

**R9 is running now**: unpinned, 6000 steps, checkpointed every 1000, to be scored on the direct
route. The reasoning is only that the capacity question — can this class reach the gate — can be
answered by measuring `Â` directly regardless of what the training signal was doing. It is not a
claim that the distorted signal is acceptable.

**Reference point for the same class without refitting**: truncating the teacher's own Cholesky
factor to the same radius-0.2 band (computed 2026-09-12, three elimination orders — packet, RCM,
raster — agreeing) drops only 2.5–2.6% of the factor's Frobenius norm and gives D/d = 0.030–0.032,
μ ∈ [0.092, 86–88], with ~294–300 directions more than 10% off. Adding a rank-k softening
correction to that truncation brings the over-stiff side to μ_max = 1.016 / 1.0038 / 1.0011 at
k = 512 / 1500 / 3000; the over-soft side (μ_min ≈ 0.09) is not reachable by softening.

**The network's actual head bounds**, for reference (these were *not* applied in the run above):

```
L diagonal   = √(S0·w) · exp(3·tanh(dg/3)),  S0 = 0.01, w the node support weight
L off-diag   = tanh(·) · min(D_i, D_j) · off_scale · exp(−dist/decay),  off_scale = 10, decay = 0.03
M            = 0.1·tanh(·) · exp(logscale)   [in the bounded variant]
```

### D.3 What D.2 does and does not settle

It gives a per-level cost distribution on the real graph, which the small bodies could not. Under
this model a network replacing only leaf construction would save about 0.1% of the elimination
work.

It does not give per-level construction, factorization, storage or application timings — only
symbolic flops and dense front sizes. It is one seat and one cut plane. It uses geometric
bisection, not a quality ordering. And it says nothing about whether a tree-structured operator is
easier or harder to learn than a single-shot one, which is a separate question.

**On the delivery cost.** An earlier version of this briefing stated that the `O(q²)` deliverable
is unavoidable. That applies to writing out every entry of `S`. It does not follow for an implicit
operator that keeps all `q` interface degrees of freedom and answers `u ↦ Su`; any single column
remains available as `Se_j`. Keeping the whole interface while declining to expand the matrix is
not port reduction. An implicit tree is not free either — internal factors, tree construction and
each application would need timing, none of which has been done.

The registered execution target in the checked-in configuration is a 64-core host that is no

with both authorization flags left false and no checked-in file modified. The code's own comment
states that a new host is a new registered target rather than a code change. Anything produced

## 10. Open questions

Listed without a preferred answer.

1. B.3 measures the preconditioner route end to end: on a geometry never seen, predicting `log c`
   from local geometry and applying the `(B∘B)` map leaves a median curvature spread of 16.8 over
   twelve seats, against an oracle floor of 1.13–1.21. Whether ~17 is sufficient in practice is
   untested — it says one learning rate can serve all columns, not that the fit succeeds — and no
   run has yet used a predicted scale. The map is a diagonal approximation, so 1.13–1.21 is a
   floor this route cannot go below without computing more of `C = BᵀA⁻¹B` than its diagonal.

2. The local class reaches direct-route D/d 0.034952 at step 1000 unpinned and 0.096171 pinned,
   against 0.030–0.032 for a truncation of the teacher's own factor and 2.11e-5 for a free dense
   factor. No run has been carried to 6000 steps under a signal that is both exact and
   unconstrained, so the class's reach is not established either way. The bounded-head version
   has still not been run, so the cost of the head bounds is unmeasured.

3. The rigid solve residual grows from 1e-15 to 1e+29 over 300 steps when unpinned. Whether this
   is driven or diffusive, and whether an effective fit in this parameterization requires it, are
   both open. C.5 lists one untested candidate mechanism.

4. Whether evaluating `logdet(B K₀ Bᵀ)` directly is affordable. The flop estimate is 4.9e12 per
   forward, about 4× the current step cost with backward, but this has not been implemented or
   timed.

5. D.2 gives a per-level flop distribution on a real GP coupling graph but no per-level timings,
   on one seat, under geometric bisection rather than a quality ordering. Whether a tree-structured
   operator is easier to learn than a single-shot one is untouched by it.

6. Nothing here addresses generalisation of the operator itself. A, C and D fit or profile one
   fixed label with the teacher available; only B.3 holds geometry out. No geometry front-end has
   been attached and no cross-geometry operator training has been run.

7. On the teacher side, the items in §3 marked "not established" remain open, in particular the
   full-trace spectrum comparison against an independent reference, and assembly of general
   oblique CUT structures rather than FULL cells.

## 11. Claims withdrawn during this work

Recorded so that a reader does not build on them.

1. **"The residual gate was measuring a quantity the objective barely depends on."** The audit
   behind this was placed one line after `opt.step()`. `FreeScaledModel.forward` returns its `M`
   parameter directly, so the operator held post-step `M` against a Cholesky factor built from
   pre-step `M`, and the audit measured that inconsistency. Its refine-0 residual read 1.3e-2 at
   step 100 while the training path read 1.3e-14 for the same step.

2. **"The student is converging to the physically correct rigid-singular operator."** The six
   rigid zero modes come from the recovery `Ŝ = BᵀÂB`, not from `K₀`. `K₀(α) = BᵀAB + αUUᵀ`
   gives the same `Â` for every `α`.

3. **"Six eigenvalues each shrank by 3.2e-40."** A log-determinant is a product; attributing it to
   exactly six modes, equally, was an assumption, and the solves feeding the number were losing
   accuracy.

4. **"Past step 225 the objective's value and gradient are not trustworthy."** Both too strong and
   too weak. The value is wrong by 2.47× at step 1000, and the fit still improved on `Â`.

5. **"Pinning a gauge cannot bias the fit."** True only if the model can realize any rigid block
   independently of `Â`. With `L` banded this is not established, and the pinned run trails the
   unpinned one by 2.75× on the direct route.

6. **"The `(B∘B)` pullback is exact."** It keeps only the diagonal of `C = BᵀA⁻¹B`, whereas
   `(A⁻¹)_jj = (BCBᵀ)_jj`. The 1.13–1.21 oracle residual is the approximation's error.

7. **"The `O(q²)` deliverable is unavoidable."** Applies to writing out every entry, not to an
   implicit operator on the full interface.
