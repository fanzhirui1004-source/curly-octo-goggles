# 状态总结初稿的核对修正清单（10-08）

说明：这里的勘误多数指向 NIGHT_LOG §3.0、§9、§10、§13、§15 和提纲中措辞不严或范围不准的地方，原文暂未改动。第 19 条（run.sh 参数）经主会话核对不成立。

## 修正清单

依据：NIGHT_LOG、STEP0/HANDOVER、full16/SUMMARY.md、仓库里的原始 JSON（lat1、ldg、cut、tau、wpdil、cost）和 src_v2_wip 代码，逐条核对过。

### (a) 数字错误或没有依据

1. **§2.1 校正预算**
   - 原文：「每加一个循环，误差约降 5 倍」
   - 改为：「第 2 个循环把误差降 4.8–5.5 倍。从 c2 到 c4（再加 2 个循环）合计只再降 3.9–7.2 倍，约每循环 2.0–2.7 倍，收益递减。」
   - 依据：日志 §3.0 表，如恒等 0.072/0.013/0.0018%，x×2 2.66/0.50/0.109%。日志 §3.0 和提纲主张 1 写法相同，也要勘误。

2. **§2.1 拉伸律**
   - 原文：「c 在 κ = 1.25 时为 3.4–3.8%，κ = 2 时为 5.7–7.5%」
   - 改为：「κ = 1.25 为 3.4–3.8%；κ = 1.5 为 3.8–5.1%；κ = 2 为 5.4–7.9%。」
   - 5.7–7.5% 只是 stretch16 的三个映射，漏了 budget16 的 x×2（5.4%）和 x×0.5（7.9%）。

3. **§1 均匀化范围**
   - 原文：「比映射均匀化（偏刚 10–56%）准两个数量级左右」
   - 改为：「逐胞重算的均匀化偏刚 7–51%，廉价张量误差 5–190%。c2w 在同一载荷分量上小 35 倍以上，多数情形约两个数量级。」
   - 下限 7.3% 来自 τ = 0.42、4³、y×2 的 y 载荷。日志 §13 第 3 点写的「τ = 0.42 时 9–16%」也应改为 7.3–15.6%。

4. **§2.3 c1 随机载荷**
   - 原文：「c1 的随机载荷误差 1.2–2.6%：胞中心 κ 只有 1.07–1.28 时也是如此，原因是角部局部剪切激发了弱 box 节点模态」
   - 改为：
     - 1.2–2.6% 只出现在扭转梁（2.4–2.6%）、扭转梁斜切（1.2%）和 Bézier（1.9%）上。
     - 弯曲板和弯曲板斜切只有 0.20–0.22%，而它们的胞中心 κ 是 1.17–1.20。
     - 决定因素是胞内局部畸变，不是胞中心 κ。扭转梁角部局部剪切 γ ≈ 0.5（局部 κ 约 1.6），这一条只适用于扭转梁。Bézier 胞内 κ 最高 2.47。
   - §4.1 步骤 0.4 里的「c1 在 κ = 1.07–1.28 的贴体格架上随机载荷就有 1.9–2.6%」同样要改。

5. **§2.3 解层面误差**
   - 原文：「…Frobenius 范数，由随机载荷主导」
   - 改为：删去「由随机载荷主导」。代码里的 `solution_rel_err` 只存 5 列合并后的值，判断不了哪一列占主导；要报告位移场精度，需要逐列存储。日志 §9 把解距离列在「随机载荷」下面，也不准确。

6. **§2.5 施加速度**
   - 原文：「施加慢 7–13 倍」
   - 问题：7–13 倍是自动微分版本的数字（cost2：c1 6.9–8.0 倍，c2w 11.1–12.8 倍），而表里列的是显式伴随的计时。
   - 改为：「显式伴随施加 16 列：对 fp32 精确算子，c1 约 8 倍、c2w 约 14 倍；fp64 精确算子 16 列反而更快（0.051–0.065 s），对它分别约 10 倍和 17 倍。」
   - 显式伴随只测了 2 个胞（homogP_t02200、2004_d0_v2）。

7. **§2.5 显存比**
   - 原文：「省 2.2–3.2 倍」
   - 改为：「2.2–3.3 倍」。fp64 精确为 9.96 GB，学习为 3.02 GB。

8. **§2.1 最坏方向表头**
   - 原文：「已收敛」
   - 改为：「有效性标记通过（min Ritz ≥ 1 − 1e-4）」。
   - 「前半个基与全基一致」只对恒等无片版本和 worst_strx2fix 报告过；wp3 只记了「48 对全部有效」。

9. **§2.1 最坏方向的覆盖范围**
   - 原文：「旋转 30°、扭转 10°、弯曲的最坏方向还没有重算」
   - 改为：「重算过的只有恒等、扭转 30°、x×2（有片和无片）和剪切 0.3（只有无片）。其余 20 个映射的旧最坏值全部作废，未重算。」
   - 另外，full16/SUMMARY.md 的 worst 列没有勘误标注。

10. **§4.2 验收标准**
    - 原文：「精确柔度和均匀化与旧运行逐位相同」
    - 改为：「精确柔度相对差 ≤ 1e-9。」
    - 依据：wpdil 与 §13 对同一格架的两次运行，精确柔度差 2.8e-12 到 2.1e-11，不是逐位相同；§14.1/14.2 用的就是 < 1e-9。
    - 均匀化只有在同样传 `--m 4,8` 时才可比，`lat_global` 默认是 `--m 2,4`。

11. **§2.6 构建时间**
    - 原文：「c2w 稠密构建时间几乎不变（487 → 508 s/胞）」
    - 补注：这个对比同样混入了 rigid64。单独开 rigid64 时，twcut22 的 c2w 构建从 356 s 变为 368 s（+3.4%），所以片半径本身的影响约 1%。

12. **§3.6 第 7 条**
    - 原文：「§0 记录 10-01 晚你授权自主推进」
    - 改为：「NIGHT_LOG 开头（§0 之前）记录 10-01 晚授权自主推进、『可做小规模数据生产』；HANDOVER §2.4 写的是『生产性的 GPU 运行先告诉作者，作者同意后再跑』。」

13. **小问题**

    - 「PCG c1 多 4–13%」只对 κ = 2 成立（恒等为 0–0.5%）。

### (c) 遗漏的重要结果和问题

17. **刚体陷阱没写**（主张 1 的直接证据）。
    - 照 P1 参考坐标分离（V0ref）时，刚体延拓能量在旋转 30° 下为 0.14，拉伸下为 5–7e-2，扭转 30° 下为 2.8e-2。
    - 物理刚体分离下为 1e-12 量级。
    - 单元层面（STEP0 U5）：参考坐标刚体模态残差约 1e-3，物理刚体模态为 3.5e-16。

18. **断点续跑可能误跳过弯曲板。**
    - `lat_global` 每算完一个代表胞、每算完一个场，都会写一次输出 JSON。
    - 所以失联时正在跑的 τ = 0.22 弯曲板，可能已经留下一个不完整的 JSON。
    - 如果 `run.sh` 只按「文件是否存在」跳过，这个算例会被漏掉。`run.sh` 不在仓库，无法核对。

19. **`run.sh` 必须显式传的参数。**
    - `lat_global` 默认 `--m 2,4`，旧运行都是 4,8。
    - `lat_mapped` 默认 `--fields c1,c2w,c4w`、`--shapes 2x2x2,3x3x3`。
    - 两者都默认 `--fast 0`。

20. **JSON 溯源问题。** `fast = 0` 时，args 里仍记 `rigid64 = 1`（默认值），但实际是 fp32 刚体。配置矩阵要按「fast 且 rigid64」判断，不能只看 rigid64 字段。

21. **`a0_worst` 走的是 fp32 刚体。** 它用 `a0_eval.MappedGeo` 的自动微分路线（fp32 刚体、单个 A3 循环）。要在推荐配置下重测，除了加循环数和片半径参数，还要能走 fp64 刚体，例如改用 `MappedFastOp`。

22. **大格架的硬障碍。**
    - §9 已记录：6³ 的 q1r 粗空间稠密矩阵约 26 GB，OOM。
    - 胞各不相同的格架如果要精确参考，每个不同胞都要一个稠密 S（fp64，每个 1.7–3.4 GB），胞数到 100 以上时不可行。
    - P1 的 `lat_scale.py`（流式、无精确参考）可以作模板。

23. **按 κ 选循环数的规则**从未在格架层面验证（§9「待做」）。规则里的 κ 应取胞内最大值，不是胞中心值。

24. **统一重跑混杂了两项改动。**
    - 统一重跑同时改了片半径和刚体精度，所以恒等格架 τ = 0.32/0.42 的界违例即使消失，也分不清是哪一项修好的。干净消融应加上恒等 τ = 0.32 的 3³/4³（半径 2 + rigid64）。
    - 单胞代理 `diag_rand` 的所有变体都开了 rigid64，所以半径效应本身（降 3.9–5.5 倍）不受这个混杂影响。

25. **实验范围没写清。**
    - 格架只用了 P1 的均匀厚度周期胞（homogP）和同族的切割体。
    - 边界条件都是一端固支、另一端面加载。
    - 应写进 §4.0。

26. **转动类共用在 τ = 0.32/0.42 上没核对过。** 这两个厚度的弯曲板、扭转梁都是 `--check 0`。

27. **本地环境限制。**
    - 容器只有 CPU 版 torch（4 核、15 GB 内存）。
    - 没有胞体、A3 检查点和 cuDSS。
    - `teacher` 的 `OPL_DEV=cpu` 只支持不做分解的单元测试。
