# src_v3 改动记录

每项改动都在 8 胞元 hlat222 上核对（表 5 路线，FINAL3 参数，`scripts/t5.sh` / `scripts/census.sh`），并与原样 src_v3 的基线比较（`results/base`）。

## 核对标准与噪声底

- **PCG 次数**：必须完全相同。
- **柔度**：相对差 ≤ 1e-7。原代码重跑的噪声约 1e-8。
- **每胞元灵敏度**：交接文档要求相对差 ≤ 1e-6，但原代码本身重跑就达不到。
  - 原样 src_v3 重跑一次（`cen0`），与基线最大相差 1.83e-6；
  - 只开开关的三次运行，最大相差 1.4e-6 到 2.1e-6；
  - 噪声来自 index_add_、Triton 散射等原子加的求和顺序，以及 PCG 解约 1e-8 的差异。
  - 因此灵敏度按"不超出原代码的重跑噪声带（约 2e-6）"判定。
- **单胞元 Ŝ**：相对差 ≤ 1e-7（`scripts/v3_shat.py`）。

单胞元 Ŝ（大胞元 hlat222_000 / 板胞元 plateS24_040，`results/sw`）：
- 三个全开时，B=1 从 40.0 ms 降到 33.3 ms，B=3 从 72.6 ms 降到 54.6 ms；

- 输出差 ≤ 4.6e-8。

结论：在现在的设置下（OPL_COARSE_PIVOT_FLOOR=1e-7），三个开关在 8 胞元上都不变慢，PCG 次数也不变。

2026-09-28 的 92 胞元 hlat554 第 4b 轮当时还没有主元下限（10 月 3 日才加）。日志只有 FRONT_END 一行，没有 ITERATION，所以当时的迭代次数无从得知。

推测的原因（未证实）：没有下限时，有些胞元的粗网格矩阵近乎奇异，显式 fp32 逆放大了误差，使 PCG 停滞，于是"变慢"实为迭代次数大增，而非核函数变慢。src_v3 改用打包的粗网格逆时，会对每个胞元检查逆的精度，不合格就退回三角求解（见下文 S2）。

## S1：状态瘦身第一批（默认开，OPL_V3_SLIM=0 可关）

| 内容 | 文件 |
| --- | --- |
| 预热后丢掉不再读取的状态：模型的每几何缓存（FastNet 只留端口节点和 U-Net 各层的 dense_idx）、geo 的 fp64 刚体模态（FastNet 有 fp32 副本）、geo.nd（主机）、Cell.Qall（只有分解路线用，改为按需计算） | fastnet.slim / slim_deploy，teacher |
| 每个模式只存一份常量：T_m、上三角、fp32 副本、81×81 对称下标；网络参数派生量（W、W^T、卷积核、W_in/W_out）标记为共享，不再随每个胞元流式传输 | teacher.shared，fastnet._share |
| fp32 矩不再单独存一份，用到时从 fp64 矩逐块舍入（数值相同） | teacher._Kfp32.m32 |
| fastidx 的行收集改为 Triton 核，去掉每个下标张量上缓存的 int64 平坦下标（大常驻胞元在 B=3 时约 360 MB；流式胞元每次装载都要重建） | fastidx |
| 流式胞元的所有张量都参与流式（原来小于 1 MiB 的留在 GPU 上，每胞元约 15–30 MB）；共享张量除外 | stream_ops.MIN_BYTES |
| 解包改用整数下标，不再用布尔掩码（布尔掩码会让主机等复制流） | stream_ops._unpack_tril |
| K_PP 主机三元组的下标改为 int32 | lat_scale，opt_design |
| K_PP 三元组只由因子持有；建 CSR 后、cuDSS 分析之前释放三元组，并清空 PyTorch 缓存（24 胞元板上，分解 K_PP 时有 5.5 GiB 已保留但空闲的缓存）；记录 cuDSS 显存估计 | lat_precond，teacher.SPDSolver |
| opt_design 一次分析结束时用 drop() 而非 release()（release 会把整个流式状态复制回主机张量再丢弃，24 胞元时多 3 GiB 主机峰值） | stream_ops.drop，opt_design |

## S2：胞元粗网格求解（默认开，OPL_COARSE_PACK=0 可关）

| 内容 | 文件 |
| --- | --- |
| 粗网格逆：由 fp32 因子求显式逆（同 OPL_COARSE_INV），按对称 64×64 分块打包只存下三角（9276 维时 165 MiB，稠密 328 MiB），每次求解是一个 Triton 核（打包对称矩阵 × 窄矩阵，真 fp32 点积）。每个胞元在预热时检查：逆作用于 4 个种子向量，与 fp64 求解的相对差超过 OPL_COARSE_INV_TOL（默认 1e-4）就退回稠密 fp32 因子 + 两次三角求解（src_v2 的做法），防止近奇异的粗网格矩阵（见上文 92 胞元的推测）。 | trainlib._coarse_pack，symtile |
| 粗网格延拓无矩阵化：src_v2 把 V 和 V^T 存成 int64 下标的 COO（大胞元约 94 MiB）。现在只存列映射（int32）、列缩放 1/d（fp64）和节点网格号（int32），共不到 1 MiB；核内按原公式重算 Q1 帽函数权重（精确的二进分数）乘 1/d 后一次舍入到 fp32，与原来存的数值相同；V^T r 用 fp32 原子加。 | coarse_mf |

单胞元（hlat222_000，B=3）：粗网格求解 3.58 → 0.45 ms；逆与 fp64 求解差 2.7e-7（原 fp32 三角求解为 6.3e-7）；Ŝ 输出差 3.6e-8。
