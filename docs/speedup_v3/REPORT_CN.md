# NICE 部署代码提速与省内存报告（src_v3）

> 草稿：第 1、4、5、6 节的数字等终测（`scripts/final.sh`）完成后更新。逐项改动的细节和核对见 `CHANGES_CN.md`，脚本在 `scripts/`，原始结果在 `results/`。

## 1 结论（暂定）

同样的条件（同一台 RTX 5090 32 GB、同一模型、同样的板算例和表 5 点阵、同样的 PCG 容差和命令行参数），src_v3 与 src_v2 的结果一致：PCG 次数完全相同，柔度相对差不超过 8e-8，灵敏度在原代码重跑的噪声带内（约 2.5e-6）。

- 能算的规模：原代码 110 胞元板已用到 30 GiB 显存，135 胞元在 cuDSS 分配时失败；src_v3（S1–S6）算到 162 胞元，显存峰值 21.6 GiB，PCG 阶段每多一个胞元约多 0.05 GiB，按此外推 32 GB 卡在 PCG 阶段约到 400 胞元（终测核实）。
- 速度：51 胞元板一次分析 544 → 298 s（−45%），其中求解 360 → 155 s（−57%）；hlat222 77 → 52 s（−32%，单流）。
- 主机内存：S1–S6 每胞元约 0.53 GiB（原来约 0.7）；S9 为了速度每个满胞元多存 0.2 GB（主机内存紧张时可关）。

## 2 条件与核对标准

- 机器：AutoDL RTX 5090 32 GB，主机 754 GB（容器 16 核）；PyTorch 2.8.0+cu128，Triton 3.4.0，cuDSS 0.8.0。
- 模型 A3_2grid（mgno2，F=32，H=4，3 层网格，smooth_k=8，粗空间 Q1_17），OPL_CONV_FP32=1，不用 TF32 / fp16 / bf16。
- 板算例：ST20 的板（`plateS<N>`，第 0 轮设计，opt_design `--fast --table5` 路线，`scripts/plate.sh`）；162、190 胞元按同一规则用 gen_hlat 生成。点阵：表 5 的 FINAL3 参数（`scripts/t5.sh`、`scripts/census.sh`）。
- 核对：PCG 次数必须相同；柔度相对差 ≤ 1e-7；每胞元灵敏度不超出原代码重跑的噪声带；单胞元 Ŝ ≤ 1e-7。灵敏度的 1e-6 要求原代码自己就达不到：同一代码重跑两次，每胞元灵敏度最大相差 1.4e-6 到 2.5e-6（原子加的求和顺序和 PCG 解 1e-8 级的差异）。

## 7 发现的问题

1. **灵敏度的噪声底。** 交接文档要求灵敏度相对差 ≤ 1e-6，原代码重跑就有 1.4–2.5e-6，因此按噪声带判定。
2. **fp32 修正中共用单元刚度会造成同向舍入。** 完全单元的矩由原子加求和，末位各不相同；任何一个共用的 fp32 矩阵都与各单元自己的矩阵在许多元素上差约 1 个末位，并对上千个单元同向。hlat222 的柔度因此变化 3.2e-6、灵敏度 3.6e-4，所以只在 fp64 中共用。教训：舍入差异若对大量单元同向，就不再是"噪声"。
3. **cuDSS 前 PyTorch 缓存占显存。** 24 胞元板分解 K_PP 时有 5.5 GiB 已保留但空闲的缓存，这很可能是原代码 135 胞元失败的原因之一；现在规划前清空缓存，并有混合内存后备。
4. **K_PP 装配的瞬时显存。** 拼接所有胞元的三元组再 torch.unique，88 胞元起成为显存峰值（6–11 GiB），而且合并好的三元组在 A Z 期间一直占着显存。
5. **流式缓冲复制到可分页内存。** 每个流式胞元 0.35 s，改为先锁页。
6. **9 月 92 胞元"开关变慢"。** 当时还没有粗网格主元下限，近奇异的粗网格矩阵的显式 fp32 逆可能使 PCG 停滞；S2 的打包逆带每胞元精度检查和后备。
7. **Ŝ 的 CPU 发射开销。** 一次 Ŝ 约 1770 次核启动、CPU 约 18 ms；Ŝ 能被 CUDA 图整段捕获（重放 0.19 ms），但多个图在多个流上并发重放时挂起（疑为 cuBLAS 工作区），未采用。

## 8 默认不开的选项和未采用的尝试

- OPL_V3_SLOTS=recompute（S5）：省主机内存，Ŝ +30%。
- OPL_V3_KE64=form：不保存 fp64 部分单元刚度（每个满胞元省 0.2 GB 主机内存，Ŝ +4 ms）。
- OPL_V3_STREAMS=1：省约 1.3 GiB 显存，求解慢约 12%。
- OPL_V3_PIPE_BODIES=1：几何生成与前端重叠（终测前单独测）。
- 未采用：融合鬼面乘积（更慢）、整层融合超边核（不快于 S10，B=3 编译不完）、单读对称 symv（慢 2–3 倍）、fp32 修正中共用完全单元刚度（结果变化超标）。
- 乙类（会改变结果，未做）：K_PP fp32 分解、胞元粗网格 fp32 直接分解。
